Summary

Goal
Signal a return to the heartbeat page with a restrained best-effort haptic.
Source
Use the browser Vibration API after foreground-return events.
Surface
visibilitychange, window blur, and window focus in index.html.
Schema
None.
Mobile
Uses device haptics only where the browser exposes navigator.vibrate.
Open Qs
0.

Algorithm

  1. Mark the page inactive after visibilitychange to hidden or window blur.
  2. On a visible or focused page, clear the inactive flag and request navigator.vibrate([16, 36, 24]).
  3. Skip the request without error when prefers-reduced-motion matches, navigator.vibrate is unavailable, or the browser rejects the request.

Decisions

IDChoice · Rationale
D-001Use one [16, 36, 24] haptic on foreground return. It marks the return without producing a continuous vibration.
D-002Honor prefers-reduced-motion. The visual motion preference also suppresses this sensory cue.

Tradeoffs

IDPicked over Rejected · Reason
T-001Foreground-return haptic over one haptic per heartbeat. It avoids sustained device vibration while the page remains open.

Assumptions

  • A-001 · Interpret “comes back” as returning from a background tab or unfocused window. If wrong: move the haptic to a different page event.

Reversibility

R-001 · low. Remove wasInactive, vibrateOnReturn, and the foreground-return listeners from index.html.

Definition of done

  • Returning to the foreground requests one short double haptic on supporting browsers.
  • Unsupported browsers and reduced-motion users retain current behavior without errors.
  • Browser smoke checks pass.
